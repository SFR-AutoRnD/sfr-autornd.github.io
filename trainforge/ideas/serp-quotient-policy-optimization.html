SERP-Quotient Policy Optimization

Train the policy on distinct search-result frontiers instead of distinct query strings. Queries that retrieve the same ranked evidence share one optimization unit, preventing paraphrases from repeatedly consuming exploration credit.

Method at a glance Pool query probability before applying the learning signal.
Optimization unit

Runtime tools
Unchanged search and fetch

01 · Training problem

Different strings can buy the same evidence.

A research agent can appear to explore while issuing lexical variants that expose the same ranked results. A string-level objective treats every variant as a separate action, so one unproductive result neighborhood can receive repeated credit and occupy a large share of the tool budget.

This method changes the unit that receives credit. The model still writes ordinary search queries, but training identifies queries by the evidence frontier returned by the environment.

02 · Learning principle

Optimize result-space exploration, not paraphrase volume.

When two queries return the same observed search frontier, their probability mass should be pooled and updated once at the class level.

03 · Training recipe

Build a quotient action space from real tool observations.

The quotient exists in the training pipeline; the deployed model continues to emit normal query text.

Trajectory data

Keep the search boundary intact

Each record retains the model state before search, the emitted query, returned result identifiers and ordering, later fetches, remaining tool budget, and the trajectory outcome. Equivalence comes from environment observations rather than a language-model similarity judgment.

Class construction

Canonicalize the observed frontier

Derive a stable signature from the returned result set and ranking, then assign queries with the same signature to one class. The signature rule, normalization, and collision handling belong in the run contract so classes can be reconstructed exactly.

Supervision

Attach credit to the class

Compute the learning signal from the downstream trajectory, then bind it to the observed result class. Member queries do not receive separate exploration rewards merely because their strings differ.

Objective

Pool policy mass before the update

Aggregate the probability of all member queries into one quotient-action probability and optimize that pooled mass. The token-level path remains differentiable through the member queries while the credit decision is made at class level.

04 · Update sequence

One training batch, step by step

  1. Sample matched research trajectories with complete search responses.
  2. Locate each search decision and reconstruct its observed SERP signature.
  3. Group query actions that map to the same signature within the declared comparison scope.
  4. Aggregate their policy mass and assign the downstream advantage once.
  5. Backpropagate the quotient-level loss through the query tokens.
  6. Log both class mass and member-query mass for later fidelity checks.

05 · Deployment behavior

No new inference-time tool

  • The model emits a standard search query.
  • The search and fetch interfaces remain unchanged.
  • No semantic-query classifier is required at runtime.
  • The intervention is carried by the trained policy weights.
  • Tool budgets and evidence verification stay independent of the quotient loss.

06 · Causal controls

Isolate the quotient update

  • Use identical trajectory rows, order, checkpoint, and update budget.
  • Keep search, fetch, verifier, and tool-call limits fixed.
  • Compare against string-level credit on the same actions.
  • Never use target answers to construct a result class.
  • Bind every saved checkpoint to its class-builder configuration.

07 · Fidelity boundary

The authored mechanism still needs code-level proof

  • Confirm that live code pools probability at the result-class level.
  • Confirm that class signatures use recorded SERP content only.
  • Inspect collision and singleton-class rates.
  • Formal novelty inventory currently places the method near prior search-space-compression work.

09 · Implementation checklist

What must be true before attributing an effect to the method

  • Publish the exact signature construction and class statistics.
  • Trace a sample gradient from pooled class mass back to its member queries.
  • Show examples where lexical reformulations collapse and genuinely new frontiers remain separate.
  • Keep performance, mechanism fidelity, and novelty as separate records.
