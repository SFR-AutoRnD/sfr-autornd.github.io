Our Mission

Research finds what is new. Development ships what is proven. Most AI agents do one or the other: they write plausible code, or they propose ideas nobody has time to test. SFR-AutoR&D exists to close that gap. Every agent in the family runs the whole arc on its own: it scopes a real target, proposes ideas, builds them, measures them under strict controls, and promotes only the candidates that survive the evidence. The output is an artifact, a patch, a checkpoint, or a finding, bundled with the tests and measurements that justify it.


We started with the two problems closest to our own work. SFR-AutoR&D-Engineer does performance research on production code, from open-source dataframe and vector-search libraries to the RL stack that post-trains our models. SFR-AutoR&D-TrainForge does the same for model training: give it a baseline model and a target, and it returns the best verified checkpoint. Both share one research loop, one evidence bar, and this page as their home.

How SFR-AutoR&D Is Designed

Every sub-project runs the same loop. Only the target changes: a hot path in a production library for SFR-AutoR&D-Engineer, a model and a benchmark for SFR-AutoR&D-TrainForge.

🧪

Built, Run, and Measured

Every candidate is built, run, and measured against the unmodified baseline on the same hardware and inputs. Code changes get paired runs across multiple seeds; training ideas get real optimizer updates and held-out scoring.

✓

Correctness Is a Gate

Patched code must produce exactly the same outputs as the original, down to the sign of a floating-point zero. A candidate model is scored on a frozen evaluation bound to its checkpoint. Any observable regression means automatic rejection.

📊

Statistics Before Headlines

Every reported number carries confidence bounds from repeated measurements. A flashy median with a shaky interval doesn't get promoted, no matter how good it looks.

🛡️

Evidence-Gated Promotion

A candidate is promoted only when its evidence survives every gate. Mixed or stale evidence keeps the incumbent, whether that is the original code or the baseline model, and the record of the attempt informs the next hypothesis.

Enforced Gates
Novelty, fidelity, efficiency, trust

Four enforced mechanisms

  • NoveltyScouts search across research domains while proposer and critic agents challenge every candidate against prior work and run history.
  • FidelityA frozen specification covers data, tool use, training, and evaluation. Structure, live-path, and behavior checks enforce it before training starts.
  • EfficiencyA staged funnel rejects weak candidates cheaply, raises fidelity for survivors, and reserves final confirmation for the strongest ideas.
  • TrustEvery held-out score stays bound to the checkpoint that produced it. Verified gains are promoted; anything else preserves the incumbent.
