Extensional Name Capsule

Replace a potentially misleading function name with an anonymous symbol, then let the policy optionally query a source-sealed behavioral capsule built from one frozen identifier-only prior.

Evidence boundary Hash-bound implementation and behavioral tests; no training checkpoint
Novelty
3.57/10
Scope
Implementation-stage research candidate

01 · Diagnosis

The observed failure signal

The coding diagnostic showed that familiar names and conventional contracts can compete with public assertions. That finding is diagnostic only: it does not prove a single cause for every failed task.

The idea asks a narrower causal question. Can useful information carried by a name be converted from an unavoidable prompt feature into optional, fallible evidence that the solver may accept or reject?

02 · Causal hypothesis

What the experiment changes

A familiar name will be easier to reject when its influence arrives as optional executable input-output predictions instead of being inseparable from the solver's prompt representation.

03 · Executable design

From data to tools to training.

The four surfaces below are part of the same contract. A result is interpretable only if each surface remains bound to the run.

Data

What the model learns from

ENC-DSL-CF generates typed Python-function specifications from a ground-truth DSL. The plan contains 4,800 base training specifications rendered as 14,400 identifier variants, 800 validation specifications rendered as 2,400 variants, and 1,600 synthetic held-out specifications rendered as 4,800 variants. AST hashes, identifier roots, composition signatures, literal pools, probe pools, and hidden-test seeds are split and audited for overlap.

Tools

What the policy can do

The policy sees exactly one optional networkless tool, name_capsule, with at most one call in the native plan. Before solver inference, a frozen Qwen model generates one prior program from only the identifier and signature. The host executes it on permitted public inputs and seals the source. The tool returns only sanitized cached behavior—never the name, source, arbitrary files, hidden tests, search, network, or a Python shell.

Training

What updates the weights

The authored plan uses rank-16 LoRA. It first proposes 600 steps of execution-verified SFT across true-capsule, disabled-capsule, and raw-name modes, followed by a 60-update execution-grounded RL stage. The native interface separately pins an eight-GPU, 60-update treatment run. Because those two layers are not yet reconciled into a completed checkpoint, the page does not claim training occurred.

Evaluation

What decides the outcome

Evaluate through a hash-pinned qwen-coder manifest in a network-disabled sandbox. Primary comparisons separate anonymization alone, name plus real capsule, and anonymized prompts with aligned, disabled, or permuted capsule outputs. Report executable correctness, capsule adoption errors, call cost, and performance by helpful, misleading, nondiscriminative, invalid, and timeout strata.

04 · Causal controls

What must stay fixed

  • One frozen identifier-only prior per item; no resampling or best-of selection
  • Structural anonymization before tokenization, with taint checks over prompts, tool messages, and errors
  • Identical student initialization, optimizer, data order, decoding, reward, sandbox, and held-out rows
  • Capsule outputs are observations only—not SFT targets, reward labels, repair targets, or candidate selectors
  • Missing capsule data produces a typed error and cannot fall back to another tool

05 · Ablations

What could explain the effect

  • Anonymization only with an unavailable capsule
  • Original name plus the real capsule
  • Type-compatible permuted capsules to control for extra tokens and tool-call practice
  • Fixed capsule with an unrelated identifier swap to detect hidden lexical dependence
  • All-zero capsules to catch constant-output and ignored-index shortcuts

07 · Current state

What has actually happened

A substantial implementation exists with a frozen contract, native execution interface, hash inventory, and behavioral-test suite.

No Qwen checkpoint or matched result was found. The evidence is implementation-level, not performance-level.

The authored 600-step-plus-60-update plan and the native 60-update interface must be reconciled before compute is allocated.

08 · Failure modes

How this idea could be wrong

  • The frozen name-conditioned prior may be uninformative or actively misleading.
  • Anonymizing the identifier changes the input channel, so gains must be separated from anonymization alone.
  • The capsule may become an authority shortcut unless shuffled, disabled, and misleading strata are enforced.
  • The current training-plan mismatch is an admission blocker, not a harmless configuration detail.
