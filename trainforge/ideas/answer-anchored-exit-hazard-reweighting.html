Answer-Anchored Exit-Hazard Reweighting

Reweight verified answer and stopping tokens so the model learns to preserve a correct answer and finish, while a small pre-answer EOS hazard penalizes drifting into the 32K response cap.

Evidence boundary Matched arms trained; frozen paired evaluation in progress

01 · Diagnosis

The observed failure signal

The frozen Qwen3-4B target diagnostic scored 138/300 overall: 105/240 on Omni-MATH, 15/30 on AIME 2025, and 18/30 on AIME 2026.

Sixty-two responses reached the 32K cap. Only 4/62 cap-hit responses were correct, compared with 134/238 non-cap responses. This 49.85-point association motivated the experiment, but the contract explicitly treats it as correlation—not proof that truncation caused the errors.

02 · Causal hypothesis

What the experiment changes

If verified final-answer tokens and terminal EOS receive more learning weight, and premature EOS probability immediately before the answer receives a small bounded penalty, Qwen3-4B may serialize a correct answer before exhausting its response budget without sacrificing full-solution accuracy.

03 · Executable design

From data to tools to training.

The four surfaces below are part of the same contract. A result is interpretable only if each surface remains bound to the run.

Data

What the model learns from

Use 480 distinct, tokenizer-eligible Hendrycks-MATH training rows sampled without replacement from 6,784 admissible fit rows. The 700-row upstream diagnostic pool and all target-evaluation material are excluded. Exact and near-overlap checks are also run against the frozen 541-prompt evaluation inventory.

Tools

What the policy can do

No inference-time tools. The evaluated model has no Python, search, retrieval, or external action. This experiment isolates a token-level training objective rather than adding capabilities at evaluation time.

Training

What updates the weights

Train matched control and treatment LoRA adapters for 60 optimizer updates each, using rank 32, alpha 64, dropout 0, AdamW at 1e-4, bf16, gradient clipping at 1, and eight problems per update. Both arms compute identical loss components. In treatment only, verified final-answer anchor and terminal EOS labels receive normalized total weight 2.0, plus a bounded 0.1·mean p(EOS) term over at most 32 deterministic pre-anchor positions.

Evaluation

What decides the outcome

Reload both step-60 adapters and run the same frozen 300-row target set: 240 Omni-MATH, 30 AIME 2025, and 30 AIME 2026. Decoding uses temperature 0, an 8K prompt cap, a 32K response cap, and a 40,960-token model context. The scorer, row order, prompts, and seed are identical between arms.

04 · Causal controls

What must stay fixed

  • Same initial Qwen3-4B parameter fingerprint for both arms
  • Same 480 rows, order, tokenizer output, optimizer, seed, and checkpoint cadence
  • Both arms compute every loss component; only the treatment scale changes from 0 to 1
  • Evaluation rows and labels are unavailable to training
  • No interim one-arm subset is reported as a treatment effect

05 · Ablations

What could explain the effect

  • Primary matched control: ordinary token-mean response SFT
  • Treatment: answer-anchor weighting plus bounded pre-answer exit hazard
  • This one-seed F0 does not yet separate anchor-only from hazard-only effects; that decomposition is reserved for a follow-up if the matched result is promising

Incremental performance-track idea

The run tests whether a narrowly targeted objective helps this model and workload. It does not claim a new general learning principle.

07 · Current state

What has actually happened

Both control and treatment completed all 60/60 optimizer updates and emitted independent training receipts.

The frozen paired evaluation is still running. Until both 300-row arms complete and merge, there is no valid score, delta, or promotion decision.

This is a real trained F0—not a smoke test—but it remains a one-seed exploratory experiment.

08 · Failure modes

How this idea could be wrong

  • The cap-hit association may reflect harder problems rather than harmful delayed publication.
  • Extra EOS pressure could shorten reasoning before the model reaches a correct answer.
  • A one-seed F0 can estimate direction but cannot establish robustness.
  • Without anchor-only and hazard-only arms, a positive result would not yet isolate which component mattered.
