Qwen3.5-35B-A3B · coding training

Counterfactual Token Vetoes

Use an executable repair certificate to place negative credit on the first code decision whose replacement is sufficient to remove a failure.

01 · Diagnosis

Whole-program rejection spreads blame too broadly.

A failing program can contain thousands of correct tokens and one consequential decision. Sequence-level preference or unlikelihood training can suppress harmless shared code while giving only diffuse pressure to the token that actually changed behavior.

The target diagnostic also contains long completions, so indiscriminate negative credit becomes more severe as the amount of correct shared prefix grows.

02 · Hypothesis and novelty delta

Admit a veto only when execution localizes the counterfactual.

If one AST replacement turns a runnable failure into a passing repair, and the two programs share the complete token prefix before that edit, the first divergent decision is a defensible target for local negative credit.

Token-level unlikelihood and execution-filtered code training are established. The proposed delta is their causal admission rule: the negative token is accepted only through a runnable repair certificate, a shared-prefix condition, and independently generated distinguishing inputs. This mechanism is under literature review; novelty is not yet verified.

03 · Real-data construction

Build local certificates without target leakage.

Training examples are rejected rather than truncated when they exceed the 8K prompt, 32K response, or 40,960-token total contract.

01

Author independent references

Start from newly authored, self-contained programming tasks with two independently implemented reference solutions. Exclude MBPP, MBPP+, target tasks, and semantic near-duplicates.

02

Generate bounded replacements

Apply a preregistered library of single-site AST replacements. Retain only mutants that load and execute in a networkless sandbox.

03

Find distinguishing inputs

Search for ordinary inputs on which the failing and repaired programs disagree, then minimize the witness while requiring both references to agree on the correct output.

04

Freeze the certificate

Bind the task, programs, AST edit, shared token prefix, witness inputs, outputs, seeds, and source hashes before any optimizer update.

04 · Training objective

Positive sequence learning plus one localized veto.

L = −log πθ(c+|p) − λγ log(1 − πθ(a|p,u))

u is the shared prefix, a the first divergent token in the failing program, and γ the fraction of independently generated witnesses repaired by the replacement. The veto is omitted unless the corresponding correct token differs and the certificate passes.

05 · Matched controls and contract

Separate localization from extra training dose.

  • Compare against equal-update ordinary SFT
  • Compare against sequence-level unlikelihood on the identical program pairs
  • Ablate the certificate while preserving pair count and loss mass
  • Freeze router parameters; adapt Qwen3.5-35B-A3B with LoRA
  • Select on disjoint development tasks, then freeze the adapter

06 · Deployment

The repair machinery disappears after training.

  • Reload the selected adapter on the unchanged base model
  • Generate code through the ordinary specification-to-code interface
  • Add no tests, repair loop, Python tool, verifier, retrieval, or search
  • Keep the existing 32K response allowance

What would falsify it?

Localization must beat its matched alternatives.

  • Local vetoes are flat or worse on independent pass@1
  • Benefits disappear when loss mass is compute-matched
  • Witnesses encode stylistic or task-family shortcuts
  • Single replacements fail to cover distributed semantic bugs
  • The novelty review finds an equivalent execution-certified local-credit method
